# 相机 SDK 触发与生命周期检查

检查日期：2026-09-15。检查对象是当前设备工厂创建的智能、工业、USB、安防和体积相机适配器，以及相关解码入口。验证采用本地 SDK 接口模拟、事件回放、代码质量守卫和客户端编译，未连接现场硬件。

## 已确认并修改

| 相机 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 华睿智能相机 | 用过滤后的条码数量判断 NoRead；重复码或被规则拦截的条码会变成误报；隐藏开关未生效 | 先判断 SDK 原始解码计数。纯图片不算读码失败；已识别但被过滤的条码不再产生 NoRead；遵守触发与隐藏开关 |
| 华睿智能相机 | 打开设备时强制硬件触发；先开始码流后注册图像回调；停止后设备被置空，恢复需要重新初始化 | 按配置启用软件、硬件或连续采集；先订阅再拉流；停止解除订阅并保留设备对象；再次启动仅保留一个回调 |
| 快仓智能相机 | 空帧未检查触发开关、软件触发及隐藏设置；启动成功却保持初始化状态，可能反复绑定 SDK | 补齐空帧条件；初始化和运行状态分别更新；串行处理启动与停止；拦截停止前后会话的迟到回调 |
| 海康工业相机 | 空句柄被 `?? 0` 当成启动成功；输出模式返回码未赋值；回调注册失败后仍保留已注册标记 | 未初始化直接返回失败；检查实际设置返回码；注册失败允许重试；停止后忽略排队扫码帧和 OCR 结果 |
| 快仓工业相机 | 停止后状态为暂停，启动只接受初始化状态，无法恢复 | 暂停恢复时调用原生启动接口；已运行时重复启动不再重复调用 SDK |
| USB 相机 | 停止时销毁已绑定设备，后续启动找不到设备；上层状态未更新 | 停止保留可重新打开的设备，最终释放时销毁；成功停止更新暂停状态并发布停止事件 |
| 大华安防相机 | 初始化强制改成扫码用途，重复初始化叠加解码器订阅；停止销毁解码器，重启仍使用旧对象 | 保留配置的绑定用途；拒绝重复初始化；解码器保留到最终释放；停止时清理拍照请求并阻止暂停状态的识别结果发布 |
| 量方体积相机 | 触发模式是静态字段，多个实例互相覆盖；默认构造后初始化可能访问空 SDK；未初始化停止可能异常 | 设置改为实例字段；两种构造路径共用 SDK 创建和一次结果订阅；停止增加空对象检查 |
| 华睿体积相机 | 初始化失败销毁句柄后仍保留句柄值，重试或释放可能使用失效句柄 | 销毁后清空句柄；默认构造初始化时保存设备信息 |
| 海康智能相机 OCR 用途 | OCR 未读码分支未检查触发总开关和隐藏开关 | 补齐两项条件；此前扫码用途的电平触发周期修复仍保留 |
| 快仓智能相机 | 单相机 SDK 没有向当前接口暴露触发序号或扫描结束回调，连续空帧会逐帧上报 NoRead | 以最后一帧后 200ms 无新帧收束当前触发帧组；组内任意一帧存在原始条码即取消 NoRead，整组全部无码只上报一次 |
| 华睿智能相机 | 电平激活方式下连续帧可能逐帧上报 NoRead | 启动时读取实际 `TriggerActivation`；边沿触发保持一帧一次判定，高低电平触发使用连续帧组汇总，任意原始条码优先 |

## 验证范围

相机相关回归测试共 51 项，覆盖过滤后误报、重复码误报、纯图像、空帧开关、软件/硬件触发配置、连续触发帧汇总、同轮后续条码取消 NoRead、重复启动、失败启动后重试、停止后重启、旧会话回调、图像释放、体积设置隔离，以及原有海康触发周期与图像处理测试。SDK 模拟验证的是适配器调用顺序和事件行为。

## 尚需实机确认或补齐的能力

- 华睿、快仓智能相机：两类 SDK 当前接入接口都没有提供像海康 `nTriggerIndex + 开始/结束` 那样完整的周期边界。代码已经对连续帧执行“有码优先、整组无码一次 NoRead”，但快仓以及华睿电平模式依赖 200ms 静默窗口收束帧组。仍需实机确认现场帧间隔和快速相邻包裹间隔；这属于无原生触发号时的保守关联，不能宣称等同于硬件触发序号。
- OCR：华睿、快仓智能相机声明支持 OCR 绑定，但现有适配器没有完整接入 OCR 初始化与识别事件；海康智能相机 OCR 的多帧结果也没有套用扫码用途的触发周期汇总。需要单独补齐并实机联调。
- 量方体积相机的连续采集被 `Start` 中的提前返回禁用；华睿体积相机的单次测量方法仍是空实现。这些能力未在本次触发误报修复中实现。
- 海康体积相机使用体积结果标志发布测量事件，没有智能扫码的 NoRead 分支。连续测量的多次回调不能据此视为光电重复触发，须结合测量模式判断。
- `DaHuaReaderSecurityCamera` 是未实现的占位适配器，当前设备工厂未创建它。NVR 的录像、回放、下载流程不属于本次扫码触发验证范围。

现场建议依次验证：一个无码包裹、先无码后读到码、两个快速连续包裹、停止后再次启动、预览模式和软件触发。核对业务记录和实际分拣次数，不能只观察日志条数。
